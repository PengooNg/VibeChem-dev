**Assumptions**
- §4.7.2 (refit_per_fold vs container nodes) is open. The v1 file follows the current draft (§4.6, refit_per_fold): a container frame on the canvas is derived from the graph (validation node + the subgraph feeding its `refit_per_fold` port), so the file stores no frame field. Choosing container nodes later = format v2 + a migration (the framework this step adds). Flagged for Quan before the phase gate freezes v1.
- `jsonschema` is not in TECH_STACK §1/§11, so it is not added. pydantic is the one validator; the committed JSON Schema is exported from the same models (drift test). Checks JSON Schema cannot express (unique ids, edges to existing nodes, R50) live in pydantic validators and are named in §6.
- Unknown keys are rejected in files (`extra="forbid"`); every field change bumps `format_version` and adds a migration.
- New codes proposed in §7: `PIPELINE_FILE_INVALID`, `PROJECT_FILE_INVALID` (params `reason` ∈ `json` / `too_large` / `schema` (+ `location`) / `version` (+ `found`, `supported`)); model packages reuse `MODEL_PACKAGE_INVALID` with the same reasons plus `entry` (unexpected zip entry).
- Model package (`.vcm`) = zip of `manifest.json` (format_version, name, vibechem_version, trained_at, pipeline, states[{node_id, block_id, block_version}]) + `states/<i>/` in the T1.02b state layout. The manifest stamps block_id/version per state (R35, accepted). Which nodes go into a package and the applicability domain belong to the export / predict steps.
- `project.json` holds format_version, project_id, name, created_at, updated_at, datasets (ids), pipelines (ids); no absolute `path` (ADR-006, relative only). Backup-on-migrate (`project.json.bak-…`) is the project-open step's job; loaders migrate in memory.
- `.vcz` and the cache index: one line each in §6 (layout), implemented by their own steps (export, T2.06).
