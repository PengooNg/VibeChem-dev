## Plan
**Assumptions (A1)**
1. Same interface as T1.05: each reader returns a `TableImport` (rows = spectra, one float64 column per axis value, named by the value; text columns before them; `suggested_roles`, `warnings`). `detected_format` gains `jcamp` and `spc` (DATA_MODEL §2.5 `format_hint` already lists them).
2. Axis unit comes from the file when it is a known unit (JCAMP `##XUNITS` 1/CM, NANOMETERS, MICROMETERS; SPC `fxtype` 1 and 13 → `cm-1`, 2 → `um`, 3 → `nm`); otherwise the T1.05 guess (cm-1 / nm) is used. The user confirms at commit, as for CSV.
3. Multi-file (osp `owmultifile` behaviour, spec only): several paths → one table with a `source_file` text column first; union of axes (direction of the first file); missing points NaN; a mismatch gives a warning and `needs_interpolation: true` (DATA_MODEL §2.5 sentence). Same union inside one SPC file whose subfiles have their own x arrays (`m_xyxy.spc`). One path → the reader's result unchanged.
4. Error codes reused from T1.05 (`IMPORT_FORMAT_UNKNOWN`, `IMPORT_FILE_INVALID`). Proposed additions in DATA_MODEL §7, the way T1.05 did: warning `IMPORT_AXIS_MISMATCH` (`params.axes`: number of distinct axes); `IMPORT_FILE_INVALID` reasons `unsupported` (+ `feature`) and `axis` (axis not finite / not strictly monotonic); `corrupt` widened from "unreadable Excel file" to any unreadable file.
5. Not supported (→ `unsupported`): JCAMP compound (LINK) files and peak tables; SPC old format (0x4D), MSB (0x4C) and Shimadzu (0xCF) variants. Can be added later if Quan needs them.
