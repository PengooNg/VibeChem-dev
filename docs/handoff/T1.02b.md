## Plan
**Assumptions**
1. State files are a directory: `state.json` (`state_version`, `values`, `arrays` = ordered array names) plus one `arrays/<i>.npy` per array (position in the list, so array names never become file names: no path traversal, no case collisions on Windows/macOS). Loaded with `allow_pickle=False`. The `.vcm` model package (T2.03, DATA_MODEL §6) can zip this directory; the layout is recorded as a short proposal in DATA_MODEL §6 for T2.03 to adopt or change.
2. Invalid state files raise `ValueError` in core (no error code is defined for core; `engine/formats` maps it to `MODEL_PACKAGE_INVALID` later). Noted as an open point.
3. A stateless block has no state; "round-trips state" for it means the empty `State()` round-trips and the block still applies (tested).
4. The wrapper covers X-only, column-preserving transformers (`fit(X)`, `transform(X)`, same column count — e.g. StandardScaler). Column-changing (PCA) and y-using (PLS) estimators get their own blocks later (T1.12, Phase 6).
5. Wrapped estimator state = every instance attribute added by `fit` (snapshot of `vars()` before/after; includes the private `_x` attributes some estimators use in `transform`). Arrays → `State.arrays`; JSON values (NumPy scalars via `.item()`) → `State.values`; anything else → `TypeError` (never pickled, ADR-007).
6. scikit-learn 1.9.x becomes a `vibechem-core` runtime dependency (TECH_STACK §1, §3.1, §11 approved) → K backlog row.

**Reuse scan**
| Option | What it covers | Licence / maintenance | Effort | Risks |
|---|---|---|---|---|
| NumPy `.npy` (`np.save`/`np.load(allow_pickle=False)`) + stdlib `json` | State save/load | BSD-3, in stack | cp1, 2 files, ~80 lines | none |
| Wrap scikit-learn transformers via fit/transform + fitted-attribute conventions | Wrapper | BSD-3, in stack | cp2, 2 files, ~90 lines | estimators with object attributes → clear TypeError |

| Build own format | — | — | — | rejected |
