## Plan
**Step:** Executor interface, process pool, seeds (Size M). Done when: tasks run in warm workers with memory-mapped inputs; per-task seeds; BLAS threads = 1.

**Assumptions**
- Per-task seeds follow ARCHITECTURE §3.4 literally: one root seed per run, `SeedSequence(root).spawn(n)`, child *i* for task *i* in the order the caller (T2.08 scheduler) gives. Each child is turned into one `int` (`generate_state(1, uint64)`), because the cache key (T2.06) takes `seed: int | None` and a worker builds `default_rng(seed)`. Keeping that order stable is the scheduler's job (RISKS row).
- The pool is one `loky.ProcessPoolExecutor` per `ProcessExecutor` instance (not the global `get_reusable_executor` singleton), so the engine owns its pool; workers stay warm while it lives (idle `timeout` 300 s).
- BLAS = 1 per worker: initializer imports NumPy, then `threadpool_limits(1, "blas")` held for the worker's life (spike finding 2); `env={"VECLIB_MAXIMUM_THREADS": "1"}` for macOS Accelerate (spike finding 6; loky 3.7 `env=` documented in its source).
- Memory maps: `ProcessExecutor.share(array)` saves arrays ≥ 1 MiB once as `.npy` in the executor's spill folder and returns a `MappedArray(path)`; top-level task arguments of that type are opened with `np.load(mmap_mode="r")` in the worker. Smaller arrays are returned as-is (pickled). Bits are the same either way (spike).
- `loky_freeze_support()` moves from `scripts/bench_parallel.py` into `vibechem_engine.executor` and is called in `api/__main__.py` before `multiprocessing.freeze_support()` (ADR-004 Actions). The spike script stays as it is (record of T0.13, own workflow).
- loky pinned `>=3.7,<3.8`, threadpoolctl `>=3.8.0`; both move from the root dev group to `vibechem-engine` dependencies (TECH_STACK §11 approval).
