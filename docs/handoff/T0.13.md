## Plan
**Goal (Done when):** speed-up (1 vs N loky workers) and determinism measured on 3 OS, in plain Python and inside a PyInstaller bundle built with the skeleton's configuration; ADR-004 recommendation in `docs/spikes/parallel.md`.

**Assumptions**
1. "Inside the frozen skeleton bundle" = a PyInstaller one-folder executable built with exactly the skeleton engine's `pyinstaller_args()` (T0.11), with the benchmark script as entry. The production engine entry is not changed (spike code stays out of `vibechem_engine`, as in T0.12). The engine bundle itself does not import loky yet; the hidden imports the spike finds go into the executor step.
2. Workload: synthetic, BLAS-bound, seeded task resembling one CV fold (row subsample → least squares on a 2,000 × 1,000 float64 matrix); not a real block. Sizes chosen so CI runs in minutes.
3. Memory-mapped input = the matrix saved once as `.npy`; workers open it with `np.load(mmap_mode="r")` (the joblib auto-memmapping pattern done by hand, since loky alone has no auto-memmap; joblib is not in TECH_STACK §1).
4. Determinism = per-task results bitwise identical across worker counts and repeated runs on one OS (and frozen vs plain). Cross-OS bitwise equality is reported, not required (BLAS builds differ).
5. loky 3.7.0 and threadpoolctl 3.8.0 (both TECH_STACK §1) are added to the root dev group for the spike (review: not engine runtime deps until the executor step imports them). Transitive cloudpickle is constrained to < 3.1.3 (3.1.3 is < 2 weeks old). cloudpickle is in-process IPC only, never saved/shared (§4 pickle rule).
