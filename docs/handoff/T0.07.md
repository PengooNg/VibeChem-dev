## Plan
**Assumptions**
1. Shared test helpers live in a new module `vibechem_core/testing.py` (numpy.testing pattern): core is the lowest layer, so core, engine and native tests can import it without breaking §3.1. It needs numpy, so `numpy` becomes a core runtime dependency (already approved in §1.2; core gets it in Phase 1 anyway). pytest/pytest-regressions/hypothesis are imported only lazily or under TYPE_CHECKING, so the shipped package does not need them at runtime.
2. No root `conftest.py`: cibuildwheel runs `pytest packages/native/tests/python` with only pytest installed and the repo root as rootdir, so a root conftest importing dev tools would break the `wheels` jobs. Hypothesis profiles are loaded from `packages/core/tests/conftest.py` and `packages/engine/tests/conftest.py` (one line each).
3. Coverage thresholds (QA.md §3: core ≥ 90 %, engine ≥ 85 %) are enforced by check.py from now on; current code is fully covered. Native is reported, no threshold. App coverage is not measured (needs a new JS dependency) — shown as `app n/a`.
4. Reference results: `assert_reference(...)` appends one JSON line per check to the file named by `VIBECHEM_REFERENCE_LOG` (set by check.py); check.py renders `reports/reference_report.md` (committed, no timestamps) and the summary line `(N/M within tolerance)`. No reference tests exist yet → line PASS `(0/0 within tolerance)`.
5. Golden helper: `node_hash(array, decimals)` (sha256 of dtype, shape and rounded values; -0.0 → 0.0) and `check_golden(data_regression, hashes, path)` that names the first node whose hash changed, then delegates storage/regeneration (`--force-regen`) to pytest-regressions `data_regression` at a `testdata/expected/` path. The real golden pipeline is T2.13.
