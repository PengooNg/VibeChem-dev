## Plan
**Goal (Done when):** unit + property tests for shapes, immutability and subset consistency.

**Fields** follow DATA_MODEL.md §4.2 `Spectra` exactly: `X`, `axis {values, unit}`, `signal_unit`, `sample_ids`, `row_index`, `source_id`, `group_ids`, `y` + `y_columns` + `y_units`, `classes` + `class_column`, `metadata`, `spatial`, `history`.

**Assumptions**
1. Invariant violations at construction raise `ValueError` / `TypeError` (programmer errors, like `reference_datasets.py`). `vibechem_core.errors` arrives in T1.02a and DATA_MODEL §7 has no code for an invalid in-memory dataset; user-facing import problems keep their `IMPORT_*` codes in the readers.
2. `metadata` is held in core as a read-only mapping `column name → 1-D array (n)`: the logical "Table (n rows)" of §4.2 without importing pyarrow (TECH_STACK §3.1 does not list pyarrow for core). The engine converts it to Arrow when storing.
3. String vectors (`sample_ids`, `group_ids`, `classes`) are tuples of `str` (immutable by construction).
4. `X` and `y` may contain NaN (missing values); finiteness is checked only for the axis (strictly monotonic, finite).
5. Arrays are copied on construction and marked read-only, so neither caller nor dataset can change the other's data.
6. `subset(indices)` takes positional integer indices, keeps the given order, rejects duplicates and out-of-range values; `row_index`, ids, Y, classes, metadata and `spatial.pixel` follow the rows. An empty selection gives an n = 0 dataset (allowed).
7. `with_X(X, *, axis=None, step=None)` returns a copy with new signal values; a new `p` needs a new axis; `step` is appended to `history`.
8. `spatial` (ImageCube unfold, P2) is included because §4.2 fixes the field now; it is a small frozen record.
