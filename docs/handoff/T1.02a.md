## Plan
**Goal (Done when):** a dummy fitted and a dummy stateless block run `fit`/`apply`; the registry lists them with their metadata; error codes match DATA_MODEL.md §7.

**Assumptions**
1. API shape follows the block template (`.claude/skills/block-template`): class attributes `block_id`, `version`, `icon`, `references`, `fitted`, `inputs`, `outputs`, `params_type`; `Param(default, …)` used as a frozen-dataclass field default (it returns a `dataclasses.field` carrying the spec in `metadata`); `port(port_id, port_type, …)`; `BlockInputError(code=…, params=…)` from `vibechem_core.errors`.
2. `block_class` defaults to the first segment of `block_id` (`preprocess.snv` → `preprocess`), `tier` defaults to `P0` (the template sets neither); both can be overridden. `title_key` / `tooltip_key` are derived: `blocks.<block_id>.title` / `.tip` (DATA_MODEL §2.3 example).
3. Fit/apply split (ARCHITECTURE §3.1): stateless blocks implement `apply(<inputs>, params)`; fitted blocks implement `fit(<inputs>, params) -> State` and `apply(<inputs>, params, state)`. `State` = JSON values + named NumPy arrays (ADR-007); its save/load is T1.02b.
4. Error codes: `errors.py` holds the coded error classes (`VibeChemError` base: `code`, `params`, `message_key`; `BlockError`, `BlockInputError`). `message_key` is derived from the code as in DATA_MODEL §1 (`PIPELINE_PORT_TYPE_MISMATCH` → `errors.pipeline.port_type_mismatch`). Codes listed in §7 as defined in `core/block` are constants in `block.py` (each code defined in exactly one module, §7). Their run-time checks (`requires`, `rows_match`, `axis_match`) need the engine's input wiring and are left to T2.01; this step declares the port fields and the codes.
5. Contract mistakes made by block authors (bad `block_id`, unknown port type, duplicate registration) are programming errors → `TypeError`/`ValueError` at class/registration time, not user-facing codes (no §7 code exists for them).
6. Parameter value validation (choices/min/max) is not enforced here: §7 has no code for an invalid parameter and DATA_MODEL §5 is T1.03's job.
7. Registry: explicit `Registry.register()` (usable as a decorator), `get`, `block_ids`, `metadata()` in the `/blocks` list shape. Automatic discovery of `vibechem_core.blocks.*` waits for the first real block (T1.07) — noted for that step.
