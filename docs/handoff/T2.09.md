## Plan
**Done when:** tests for worker crash (native fallback), OOM throttling, cancel timeout, corrupt cache (ARCHITECTURE §3.6).

**Assumptions**
- No C++ kernels exist yet (Phase 3). "Native fallback" = a `Job` may carry a `Fallback(fn, block_id, kernel)`: the Python reference. Tests use a task that kills its worker (`os._exit`) as the "crashing kernel".
- loky 3.7.0 (probed): a dead worker fails every running future with `TerminatedWorkerError` (a `BrokenProcessPool`) and the pool stays broken; `shutdown(kill_workers=True)` fails running futures at once. So the executor needs `restart()` (kill workers, new pool).
- Crash: all jobs that were running are retried once, each alone (so a bystander is not hit again and the culprit is isolated), with its `fallback` if it has one (`native.fallback`, `reason: worker_crashed`). A second crash = node error without code (R58 b).
- `MemoryError` from a task (or an OS OOM kill, which looks like a crash): concurrency cap halved, `memory.throttled`, the job retried once alone; a second `MemoryError` → node error `RUN_OUT_OF_MEMORY` (proposed in DATA_MODEL §7, like earlier steps' proposals; advice in the translated text).
- Cancel timeout: `run_jobs(..., cancel_timeout_s=5.0)`; while a `cancel` event is given, `wait` polls every 0.1 s; once cancel has been set for longer than the timeout, `executor.restart()` kills the stuck workers, their nodes are `unfinished`. R58 (c) "cancel acts only when a running job ends" is in scope; a hung worker *without* cancel (no task timeout) stays open in R58.
- Corrupt cache: already covered by T2.06 `tests/cache/test_store.py::test_corrupt_entry_is_discarded_and_recomputed` (discard + recompute); no new code. Wiring the cache into runs is the runner's (T2.10).
