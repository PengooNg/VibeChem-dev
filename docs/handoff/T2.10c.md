## Plan

### Assumptions (A1)
1. Quan's option A (2026-11-28): the search block has a `search_space` parameter: ordered slots, each a list of options; an option is `{"block_id", "params"}` or `null` ("none"). The JSON value is a new parameter type `search_space` (DATA_MODEL §5.2, proposed here); its default is the default search-space file `blocks/validate/default_search_space.json`, built only from registered core blocks.
2. Block id `validate.grid_search` (proposed, DATA_MODEL §4.5); inputs `model: Model (refit_per_fold)`, `folds: Folds`; output `results: Results` (`kind = search`). Its other parameters are the `validate.cv` parameters (the same LV rule and metrics per candidate).
3. **No `model` output** in this step (DATA_MODEL §4.6 lists one for every validation block): a PLS state without its preprocessing chain cannot predict raw spectra, and the chain is not on the canvas. Recorded as an open point for Quan (DATA_MODEL §4.7, RISKS row), not built.
4. Engine: each candidate is built as a real branch of the pipeline document (chain nodes between the node feeding the model block's first input and a copy of the model block, then a `validate.cv` copy on the search's `folds`). The existing compiler (fold plans, leakage rules) and `validate.cv` do all the work, so a candidate's metrics are a `validate.cv` run of that chain by construction. Expansion lives in `vibechem_engine/runners/` (the step's file list), called by `run_pipeline`; the compiler is not changed.
5. Candidate order: the slot product in the order written (last slot changes fastest, `itertools.product`); chains equal after dropping `null` and filling default params are deduplicated, first one kept. Identity = canonical JSON of `[block_id, parsed params]` per step (same recipe as the T2.06 cache key params).
6. `Results.metrics` of the search = the metrics of the best candidate: the smallest RMSECV at its chosen LV count on its own CV curve (the value the LV rules work on; PLS1: `rmsecv`; PLS2/PLS-DA: the fitted-space curve, N28/N29); ties → first candidate. Optimistic by selection; nested CV is T2.10d. New choice → METHODS §0 N30 for Quan.
7. Bad `search_space` (unknown `block_id`, a block that is not a one-Spectra-in/Spectra-out step, an option's bad params) → `BLOCK_PARAM_INVALID` on the search node (node error at run time, §5.3), params `param_id = search_space`, `reason`, `slot`, `option`. New reasons `unknown_block`, `not_a_spectra_step` proposed in DATA_MODEL §5.3.
