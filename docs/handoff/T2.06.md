## Plan
**Goal (Done when):** key stability tests; LRU cap; corrupt-entry recovery test.

**Assumptions**
- A1. One result key per task output: `result_key(task, output, block_id=, block_version=, params=, input_keys=, seed=)` = `res_` + SHA-256 of canonical JSON (sorted keys, compact, `allow_nan=False`) of: key version, task kind, block id + version, params, inputs `[port_id, upstream result key, rule]` (sorted by port, edge order kept inside a `multiple` port), seed, fold, part, output port. ARCHITECTURE §2.2 step 4 lists block id, version, params, input keys, seed; kind, rule, fold/part and output are added because they change the result (fold/part decide what a `select` task returns; the rule is an implicit conversion).
- A2. Params are passed as parsed by `parse_params` (defaults filled), so writing a default explicitly does not change the key; `1` and `1.0` are different keys (JSON types). Dataset content for source nodes is not hashed here (the project/dataset step gives sources a content key via their params or input keys).
- A3. An entry is one `vibechem_core.block.State` stored in the T1.02b `save_state` layout (reuse); converting port objects to/from `State` is the executor's job (T2.07).
- A4. No global index file: each entry carries `entry.json` (key, size, SHA-256 per file); the in-memory index is rebuilt by a scan when the cache is opened, recency = `entry.json` mtime (touched on a hit). Avoids rewriting a large index on every put and a single corruptible index; entries are staged in `cache/tmp/` and renamed into `cache/entries/<hex>/`, so a crash never leaves a half entry. Recorded as the "cache index format" in DATA_MODEL §6.6.
- A5. One engine process owns a project's cache (`ResultCache` is not thread- or multi-process-safe for eviction). Opening the cache deletes `tmp/` leftovers.
- A6. LRU: after a put, evict least recently used entries until size ≤ cap, never the entry just written (it is about to be read). `put` returns freed bytes so the scheduler can emit `cache.evicted`.
- A7. Corrupt entry (checksum mismatch, missing file, `load_state` error, bad `entry.json`) → entry deleted, `get` returns `None` (recompute, ARCHITECTURE §3.6), logged as a warning.
- Open: `clear(scope="unused")` (§2.11) needs pipeline knowledge → API step; eviction of an entry a later task still needs → scheduler (T2.08) must handle a miss (RISKS row).

**Reuse (M, ladder):** rung 2+3 — core `save_state`/`load_state` (T1.02b layout, no pickle) + stdlib `hashlib`/`json`/`os.replace`/`shutil`. joblib `Memory` rejected: it pickles results (CLAUDE.md §4, ADR-007) and joblib was already rejected in TECH_STACK §11 (T0.13). `diskcache`: pickle by default + SQLite, not in TECH_STACK. Own glue ≈ 150 lines.
| Option | Covers | Licence / maintenance | Effort | Risks |
|---|---|---|---|---|
| joblib `Memory` | memoised function results, hashing | BSD-3, active | 2 cp | pickle files (§4 forbids), new dep, keys by function source not block version |
| diskcache | disk KV store, LRU-ish eviction | Apache-2.0, slow releases | 2 cp | pickle default, SQLite, new dep |
| Build on core `save_state` + hashlib | everything | — | 3 cp, 2 src + 2 test files, ~150 + ~150 lines | own code to maintain |
Recommendation: build on `save_state` + hashlib.
