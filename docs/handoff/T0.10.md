## Plan
**Assumptions**
1. The renderer needs the engine's port + token. ARCHITECTURE §2.1: Electron main spawns the engine and hands port + token to the renderer. T0.10 does the **dev-mode part only**: when not packaged, main runs `uv run python -m vibechem_engine.api` (repo root, `VIBECHEM_DEV=1`), reads the `engine.listening` line (DATA_MODEL §1), stops the engine on quit, and answers one IPC call `engine:connection` exposed by a sandboxed CommonJS preload as `window.vibechem.engine()`. T0.11 adds the PyInstaller bundle, supervision/restart and the packaged origin.
2. The renderer CSP gets `connect-src 'self' http://127.0.0.1:*` (the engine is on a random loopback port); everything else stays `self`.
3. e2e runs the renderer from the Vite dev server (engine dev mode only allows `http://localhost:<port>` origins; a `file://` page sends `Origin: null` → 403). Playwright `webServer` = `electron-vite dev --rendererOnly`, then `_electron.launch` the built main with `ELECTRON_RENDERER_URL`.
4. "API client generated from OpenAPI": `scripts/export_openapi.py` writes the engine's OpenAPI JSON (no server needed, `create_app(...).openapi()`), `openapi-typescript` writes `app/renderer/src/api/schema.d.ts` (committed). The client is a small typed `fetch` wrapper using those types (openapi-fetch is not in TECH_STACK §1.5). `/skeleton/run` returns Arrow, decoded with `apache-arrow` `tableFromIPC`.
5. No zustand store yet: the only state is the run result, held by a TanStack Query mutation.
6. Dataset fixed to `gasoline_nir`; raw and SNV are two plots side by side (two `/skeleton/run` calls).
7. Nightly gets an `e2e` job on 3 OS and a `workflow_dispatch` input `ref` so the job can be run on this branch before merge ("passes in CI").
