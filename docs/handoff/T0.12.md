## Plan
**Goal (Done when):** preview round-trip numbers for 2,000 × 2,000 (lines and density mode) on 3 OS recorded in `docs/spikes/transport.md`; ADR-003 recommendation (accept / change) written for the gate.

**Assumptions**
1. "Round-trip" = client sends `GET` → engine builds the preview from an in-memory 2,000 × 2,000 float64 matrix (decimate or density raster) → Arrow IPC encode → HTTP over 127.0.0.1 through the real `create_app` security stack (token + Origin) → client receives and decodes. Server compute is reported separately (`Server-Timing`), so transport cost = total − compute.
2. Clients: Python (`urllib` + pyarrow) and Node 24 (`fetch` + `apache-arrow`, the renderer's decoder, extracting the Float32Arrays as `decodeSpectra` does). Chromium rendering (uPlot) is not part of transport and is not measured (T2.12 benchmarks / Phase 4).
3. Lines mode at 2,000 spectra = request with `max_lines ≥ 2000` (all 2,000 spectra as lines, decimated to `width` = 1200 points). Density mode = default `max_lines` 500 → raster `width × 256` uint16 + mean, ±1 SD + 10 selected rows.
4. The density Arrow layout is a spike proposal only (not added to DATA_MODEL.md; the real format is fixed with the preview endpoint in Phase 4). Spike code lives in `scripts/` and `app/scripts/`, not in the engine package.
5. Synthetic data from a seeded `numpy.random.Generator`; target from ADR-003: < 300 ms.
