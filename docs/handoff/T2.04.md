## Plan

**Assumptions**
- The compiler is static: it never runs a block. The number of folds is only known at run time, so
  "per-fold expansion hooks" = a `FoldPlan` per validation node whose `expand(fold, repeat)` returns
  that fold's tasks; the runner (T2.10) calls it once the `Folds` are computed.
- Task kinds: `run` (stateless block), `fit` + `apply` (fitted block), `select` (rows of one fold,
  by `row_index`). A fitted block's `Model`/`Transform` output ports are its fit task's state; the
  other outputs come from the apply task (DATA_MODEL §4.6, block contract).
- Implicit edge conversions (§4.4) are recorded on the task input (`rule`), not as extra tasks.
- Fold source = the `Spectra` stream feeding the node that produced the validation node's `folds`
  input. Fold subgraph = nodes downstream of that stream that feed the `refit_per_fold` port. The
  fit task of each subgraph node gets the fold's `train` rows only; apply/run tasks run on the
  `train` and the `validation` stream. Inputs from outside the subgraph stay wired to the full-row
  task; rejecting the leaky ones is T2.05 (R39).
- The `refit_per_fold` source not downstream of the fold source → `PIPELINE_FOLDS_SOURCE_MISMATCH`
  (already in DATA_MODEL §7, "engine/compiler").
- `compile_pipeline` returns graph issues (from `validate_graph` plus the fold check) instead of
  raising; no tasks when there is an error.
- Not in this step (Do/Done do not name them): NaN-row removal at pipeline entry (R24/R26) and the
  ADR-010 warning recording (R31) need block execution, which starts in T2.07/T2.08. Noted, not built.

**Reuse (ponytail ladder):** rung 3, stdlib `graphlib` (topological order, as T2.02) + `dataclasses`;
minimum own code on top. TASKS lists no reuse candidate.
