## Plan
**Assumptions**
- A1. Inner tuning = an inner `validate.grid_search` on each outer training set: LVs by the LV rule, the preprocessing chain from `search_space`. Default `search_space` = `[[null]]` (one empty chain: LVs only). "Selection params" are tuned the same way once selection blocks exist (they are Spectra steps; none exist yet).
- A2. `inner_folds` = `{block_id, params}` of a fold block (decided by Quan, 2026-11-28). New parameter type `block_ref` (DATA_MODEL §5.2, proposed). The inner fold block runs on the outer fold's training rows of the fold-source stream.
- A3. Outer prediction of a fold = the inner-chosen chain + model re-fitted on the outer training rows, at the inner-chosen LV count (the fold model's first n_lv components = a refit, as in `validate.cv`).
- A4. Outer metrics = the `validate.cv` CV metrics of the out-of-fold predictions, each fold at its own n_lv (same aggregation, per-repeat mean, PLS2 / PLS-DA as in `validate.cv`).
- A5. No `model` output (as `validate.grid_search`, N30): the final model is a `validate.cv` / grid search on all rows. DATA_MODEL §4.6 lists `model` for every validation block, so this is flagged for Quan (new §4.7 point, METHODS N32).

**Reuse (ponytail ladder)**: rung 2, our code. `validate.cv` evaluation reused through one extracted function (`cross_validate`, with per-fold fixed LV counts); outer branches = `expand_search` (generalised to any params type); inner tuning = a sub-run of `run_pipeline` with a `validate.grid_search` node; scikit-learn `GridSearchCV` + `cross_val_predict` only as the test reference.
